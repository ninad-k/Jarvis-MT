# Security audit, 2026-10-30

Full-system review of Jarvis MT (`main` plus the uncommitted Sprint 2 to 5 work) before the first
public release. Companion document: [threat-model.md](threat-model.md).

## Summary

| Severity | Found | Fixed | Open or accepted |
|---|---|---|---|
| Critical | 0 | 0 | 0 |
| High | 2 | 2 | 0 |
| Medium | 4 | 4 | 0 |
| Low | 17 | 7 | 10 |
| Info | 7 | 1 | 6 |

No Critical issue was found. **No path was found by which the language model, or text it reads, can
send a write to the bridge without a gate-approved, user-confirmed, unexpired, single-use token.**
The two High issues were in the web-facing edge (a cross-origin page could drive the whole API,
including its own confirmation) and are fixed. The two bridge issues of Medium severity were fixed
afterwards: the outdated vendored ZeroMQ DLLs (BR-2) by building libzmq 4.3.5 from source and removing
libsodium, and the missing peer authentication (BR-1) by signing every bridge message with a shared key
(ADR-0016).

Core rules 1 to 10 of [SPEC.md](../../SPEC.md) were each traced to the code that enforces them and
to a test that fails when they break (table in [threat-model.md](threat-model.md#4-where-the-safety-rules-are-enforced)).

## Scope

In: `crates/api`, `crates/gate`, `crates/bridge-client`, `crates/llm`, `crates/voice`, `mql5/`
(EA, JSON parser, trade handlers, vendored binding and DLL metadata), `web/` (SPA, service worker,
microphone capture), `apps/desktop` (Tauri 2 shell), `.github/` (CI, security, release, scorecard,
dependabot, CODEOWNERS), `scripts/*.ps1`, configuration and documentation.

Not covered: the MT5 terminal and broker, the LLM providers, and the compiled EA (MetaEditor was not
run, so the MQL5 sources were reviewed but not rebuilt or executed in this review).

## Method

1. Read SPEC.md, SECURITY.md, the sprint plan, `docs/api.md`, `docs/protocol.md`,
   `docs/architecture.md`, `docs/desktop.md` and the ADRs. Built the threat model (STRIDE per trust
   boundary).
2. Traced each SPEC rule from entry point to the bridge write and looked for a bypass: LLM-to-token
   paths, CSRF and cross-origin use, kill-switch races, DEMO/LIVE enforcement, credential flow into
   logs, audit rows, the model and the browser, and the bridge's exposure.
3. Manual review of authentication (JWT algorithm pinning, expiry, cookie flags, revocation, TOTP
   replay, timing, lockout), input validation (body limits, JSON, path parameters, WAV decoding),
   the Piper process spawn, static file serving, the WebSocket, SQL (all queries are parameterised),
   the MQL5 JSON parser and trade handlers, `unsafe` and panic sites (none reachable from a
   request; the only `unsafe` is in test setup), secrets handling, Tauri capabilities and CSP, the
   service worker, workflows and release provenance.
4. Scanners (below), then fixes with regression tests, then a full re-run.
5. Runtime checks over real sockets: the running server probed with `curl` for the Host and Origin
   rules, a restart to confirm the kill switch survives, and the Vite dev workflow to confirm it
   still works without any CORS entry.

### Fix for BR-1 (design as built, ADR-0016)

The review recommended a MAC over selected request fields. The build signs the exact bytes instead,
which avoids a canonical JSON form in two languages:

- **Key.** 32 random bytes (CSPRNG), 64 hex characters, in `MQL5/Files/JarvisMT/bridge.key` of the MT5 data
  folder (the EA's file sandbox, inside the user's profile). `scripts/install-ea.ps1` creates it if missing,
  never overwrites it (`-RotateKey` replaces it on request) and never prints it. The EA reads it with
  `FileOpen` in `OnInit` and does not start without it; the API reads `[bridge] key_file` or
  `JARVIS_BRIDGE_KEY` and does not start without one. Neither logs it.
- **Messages.** Both directions: two ZeroMQ frames, `[lowercase hex HMAC-SHA256(key, frame 2), frame 2]`.
  The MAC covers the raw payload bytes. Requests carry `"ts"` in Unix milliseconds.
- **EA checks, before the arguments are parsed or `CTrade` is touched:** exactly two frames; the MAC
  (constant-time compare); `ts` within 30 s of the EA's clock; an `id` not used in the last 60 s (table of
  4096 ids, expired on a monotonic clock, fail closed when full). A failure is answered once with a signed
  `-4` "authentication failed" (empty `id` when the MAC was wrong, so the reply cannot be used as a signing
  oracle) and logged with the reason, throttled.
- **Replies.** Signed the same way. The client checks the MAC (constant time) and the `id` of every reply
  and drops the socket on failure, which defeats a squatter on the port.
- **Tests.** Mock bridge with the same rules (wrong key, missing MAC, tampered payload, replayed id, stale
  `ts`, forged reply), RFC 4231 vectors and a golden vector in Rust and MQL5, and a live run of the compiled
  EA in an isolated terminal.
- **Not covered.** The messages are not encrypted and a program that can read `bridge.key` (the same Windows
  account, an administrator) is not stopped; SECURITY.md excludes a compromised machine. A peer can still
  flood the socket with garbage (each message costs one HMAC and one reply; nothing executes).

## Residual risks

- **A program that can read `bridge.key` can use the bridge.** BR-1 keeps out other Windows users and every
  process that cannot read the key file, but not the same Windows account or an administrator, and the
  bridge messages are not encrypted. Keep the MT5 data folder inside your own profile (or restrict the file),
  run Jarvis on a PC or VPS with a single trusted Windows user, and keep `InpAllowReal` false.
- **A manipulated model can still propose** something the user did not ask for when the parser reads
  the message as `Other` (LLM-1). The preview and the 15 s confirmation are the defence; read the
  preview, especially before confirming by voice.
- **Spoken confirmation hears everything while the mic is held.** Push-to-talk narrows this to the
  moments the user presses the mic. Use headphones.
- **Login-off mode trusts the machine.** The Host and Origin rules stop web pages, not local
  programs.
- **The audit database and `.env` are plain files.** Anyone with the Windows account can read or
  edit them. Keep them in a folder only that account can open.
- **Cloud models see account figures and positions** when selected. Ollama keeps them local.

## Recommendations

1. BR-1 (MAC on every bridge request) and BR-2 (current libzmq) are fixed in the repository. Before any
   real account is used: run `scripts/install-ea.ps1` (it creates the bridge key and installs the new DLL),
   recompile and re-attach the EA, and confirm the whole chain on a demo account first.
2. Run the service as a virtual or dedicated account (SVC-1) and restrict the folder ACL to it.
3. GitHub settings to check, which this review cannot see: private vulnerability reporting enabled;

## Positive observations

- The model's toolset is a closed set of nine tools, none of which can execute; tokens never reach
  the model, and a test asserts both.
- One function sends writes, with a test that fails if another appears.
- The kill switch is checked at five points, including before each write of a batch, and now
  survives restarts; releasing it needs a fresh TOTP code that works once.
- Password hashing is Argon2id with explicit parameters; TOTP replay is prevented atomically in SQL;
  all login failures look identical and unknown users cost the same time as real ones; sessions are
  revocable and tied to TOTP resets; the JWT algorithm is pinned.
- The CSP is strict (no inline or eval script), the service worker never touches `/api`, the SPA has
  no `innerHTML` or `{@html}`, and request logs redact confirmation tokens.
- WAV decoding checks format, rate and duration before allocating; Piper receives text on stdin and
  a fixed argument list; static serving survived a Windows-specific traversal test.
- Every GitHub Action is pinned to a commit, permissions are read-only by default, forks never get
  secrets, and releases carry checksums and a provenance attestation.
- The Tauri window gives the remote page no IPC and limits navigation to one origin.
- The EA validates every field, binds only to `127.0.0.1`, refuses real accounts by default and
  never trades unprompted.
